Why pisentry

Small boards get attacked too.

A Pi with SSH open sees brute force within hours. Most security agents were built for big servers. This one was built on a Pi, for the Pi.

No eBPF needed

Most modern eBPF agents need kernel BTF. Stock Raspberry Pi OS kernels do not ship it. pisentry reads logs, /proc and files, so it runs on the kernel you already have.

Small enough to read

5,200 lines of Go and no third-party modules. The whole dependency surface is this repo and the Go toolchain. You can audit it in an afternoon.

A ranked Top 10 shows what matters this week. A cooldown turns one brute-force campaign into one alert, not five hundred.

How it works

From log line to alert in one process.

No manager, no database, no agent fleet server. Seven detectors feed one engine, and the engine feeds the tools you already run.

Signals

  • journald or auth.log
  • kernel drop log
  • /proc every 15s
  • /proc/1/net every 30s
  • /etc, cron, systemd every 60s
  • SUID walk every 6h
  • posture audit every 6h

Detectors

  • auth
  • portscan
  • proc
  • listeners
  • fim
  • suid
  • audit

Engine

  • sanitize every string
  • dedupe, 15m cooldown
  • tag with MITRE IDs
  • rank the Top 10

Outputs

  • /metrics :9817
  • JSON events
  • ntfy, Discord, Slack
  • any webhook
  • /api/top10
  • state.json

Learns first

For ten minutes it records listeners and login sources without alerting.

Alerts once

A changed file alerts once, then the new hash becomes the baseline.

Knows apt

If a package manager is running, file change severity drops one level.

Trusts no input

Every name, path and command line passes one sanitizer before output.

Keeps a budget

Thirty alerts an hour, and critical alerts get their own budget.

Event counters start at zero, so increase() sees the first event. Alert on the agent going quiet, not just on attacks.

# TYPE pisentry_events_total counter

# alert rules worth having
increase(pisentry_events_total{severity="critical"}[5m]) > 0
absent(pisentry_up)
time() - pisentry_detector_last_run_timestamp_seconds{detector=~"proc|listeners|fim"} > 900

High and critical events go to ntfy, Discord, Slack or any webhook. The URL and token come from the environment, never from the config file.

# /etc/pisentry/config.json
"alerts": { "type": "ntfy", "min_severity": "high", "max_per_hour": 30 }

# /etc/pisentry/pisentry.env  (mode 0600)
PISENTRY_WEBHOOK_URL=https://ntfy.sh/a-long-random-topic-name

Get started

Audit a Pi in four commands.

No install and no daemon. The audit exits with code 2 if anything is high or critical, so it also works in scripts.

curl -fsSLO https://github.com/MrGuato/pisentry/releases/latest/download/pisentry-linux-arm64
curl -fsSLO https://github.com/MrGuato/pisentry/releases/latest/download/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
chmod +x pisentry-linux-arm64 && sudo ./pisentry-linux-arm64 audit

Use pisentry-linux-armv7 on 32-bit Pi OS and pisentry-linux-amd64 on x86.

FAIL    high      SSH-02  SSH root login permitted       PermitRootLogin yes
FAIL    medium    SSH-01  SSH password authentication enabled
How to fix:
  SSH-02: Set 'PermitRootLogin no' (or prohibit-password if you need key-based root).
git clone https://github.com/MrGuato/pisentry && cd pisentry
sudo ./deploy/install.sh

The binary goes to /usr/local/bin, config to /etc/pisentry and secrets to a 0600 env file. The unit keeps two capabilities, a syscall filter, a read-only system and a 96 MiB memory cap.

Copy deploy/kubernetes/ into your cluster repo. The DaemonSet pins the image by digest, because this agent is root-equivalent on every node.

kubectl -n pisentry get ds pisentry
kubectl -n pisentry exec ds/pisentry -- pisentry report
kubectl -n pisentry logs -l app.kubernetes.io/name=pisentry -f | jq 'select(.severity=="critical")'

Releases after v0.1.0 are signed by the release workflow with Sigstore cosign. You need cosign 3 or later.

FAQ

Straight answers.

Does it replace Falco?

No. Falco watches syscalls from the container runtime. pisentry watches the host: logs, files, processes and posture. Run both where you can. On a stock Pi kernel, pisentry may be the one that runs.

Will it slow down my Pi?

On a 2 GB Pi 4 in k3s it uses 16 MiB of memory and 2 millicores of CPU. It is capped at 96 MiB.

Why does it run as root?

It reads /etc/shadow, other users' /proc entries and the journal. The systemd unit keeps two capabilities and the pod keeps three. Everything else is taken away.

What if an attacker gets root?

Root wins. An attacker with root can stop the agent or edit its state. Ship events off the box and alert when pisentry_up goes missing. That is the real defense.

Does it block attacks?

Not today. pisentry detects and alerts. Automated response is on the roadmap, off by default and fenced by allowlists.

Can I write my own rules?

Thresholds, allowlists and extra watch paths are config today. A rule engine for your own patterns is the next milestone.

What does it cost?

Nothing. It is MIT licensed, and it stays that way.
